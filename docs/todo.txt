48. Incoming-request/withdrawal ordering is compensated for, not guaranteed
Status: not started

Problem
- The request stream and withdrawal stream are consumed by two independent `Task`s.
- Ordering is handled by a bounded set of withdrawn request IDs consulted in
  `handleIncomingRequest`, which is correct but only verified via `Task.yield()` loops in tests
  because there is no observable "withdrawal recorded" state to await.

Affected area
- `Modules/FeatureTransfer/Sources/FeatureTransfer/Application/TransferFeatureStore.swift`
- `Modules/FeatureTransfer/Sources/FeatureTransfer/Infrastructure/LocalSendRuntimeAdapter.swift`

Recommended next step
- Merge both streams into one enum-tagged stream so ordering is structural rather than
  compensated.

57. Multi-instance launches should be prevented, not compensated for
Severity: minor

Problem
- A second LocalDrop instance sharing the same save folder currently has no guard against
  filename collisions. Rather than adding cross-process collision handling, the app should
  simply refuse to run more than one instance at a time.

Affected area
- App launch / lifecycle (e.g. `LocalDropApp` entry point)

Recommended next step
- Detect an already-running instance at launch and either bring it to the foreground or quit,
  so multi-instance usage is not possible in the first place.
